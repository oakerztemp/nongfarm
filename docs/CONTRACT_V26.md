## ปัญหาเดิม (เล่นหลายเครื่อง)
เซฟเป็นก้อนเดียว `users/{uid}` + `rev` (ห้ามเขียนทับของใหม่กว่า) · เมื่อสองเครื่องต่างมีของที่ยังไม่ขึ้นคลาวด์ (เช่นมือถือถูกปิดก่อนอัปโหลด 30 วิ แล้วไปเล่นคอม) ตอน reconcile **ก้อนที่ updatedAt ใหม่กว่าชนะทั้งก้อน** อีกก้อนไปอยู่ใน backup (เก็บ 3 ชุด ไม่มีปุ่มกู้) → ผู้เล่นเห็นว่าของหาย

## 1. รวมเซฟแบบ 3 ทาง (A: js/merge.js ใหม่, pure, ไม่มี DOM)
`export function mergeSaves(base, local, remote) -> { state, conflicts: string[] }` — base = ก้อนล่าสุดที่ทั้งสองฝั่งเคยตรงกัน (ขึ้นคลาวด์สำเร็จ), local/remote = สองก้อนที่แยกกันไป · ทุกตัวเป็น state ที่ผ่าน migrate แล้ว · ไม่แก้ input
- **ตัวนับบวกกัน** (`base + (local−base) + (remote−base)`, ไม่ต่ำกว่า 0): `player.coins`, `stardust`, `inventory.*`, `inventoryDecor.*`, `wardrobe.*`, `stats.*` (ตัวนับ), ค่าตัวเลขสะสมอื่นที่ A ระบุใน MERGE_RULES พร้อมเหตุผล
- **XP ผู้เล่น**: แปลง (level, xp) เป็น XP สะสม → บวก delta สองฝั่ง → แปลงกลับด้วยสูตรเดียวกับ `xpForLevel`/`addPlayerXp` (ไม่ให้เลเวลขึ้นซ้ำสองรอบ หรือหาย)
- **อาร์เรย์ที่มี id** (`pets`, `decor`, `incubator`, `nursery` (ใช้ pet.id), `familyEggs`, `postcards`, `expeditions`, `log` …): รวมตาม id — มีฝั่งเดียว = เพิ่ม/ลบตามฝั่งที่เปลี่ยน (ลบฝั่งหนึ่ง + อีกฝั่งไม่ได้แก้ = ลบ; ลบฝั่งหนึ่ง + อีกฝั่งแก้ = เก็บตัวที่แก้), ทั้งสองฝั่งแก้ตัวเดียวกัน = รวมระดับฟิลด์ (ตัวเลขสะสมของน้อง เช่น xp/bond เป็น delta บวกกัน; ค่าสถานะ hunger/happy/clean/health และฟิลด์อื่น = ฝั่งที่ updatedAt ใหม่กว่า)
- **อ็อบเจกต์ทั่วไป**: รวมทีละ key แบบ 3 ทาง (เปลี่ยนฝั่งเดียว → เอาฝั่งนั้น; เปลี่ยนทั้งคู่ไม่เท่ากัน → ฝั่งใหม่กว่า + บันทึกใน conflicts)
- **อาร์เรย์ไม่มี id / ช่องคงที่** (`plots` ตาม index, `claimedGoals`, `friendsMet`, `coatsSeen`, `collection`): plots ตาม index ฟิลด์ละ 3 ทาง; รายการ "เคยได้" (claimedGoals, friendsMet, coatsSeen, collection) = union (collection: ค่ามาก)
- ผลลัพธ์ผ่าน `migrate()` อีกรอบ (sanitize) · `updatedAt = max(local, remote)` · ตัวนับที่ติดลบหลังรวม (เช่นขายของชิ้นเดียวกันสองเครื่อง) = 0 และบันทึก conflict
- tests/v26.test.js: กรณีตัวอย่างจริง (ทำอาหารเครื่อง A + เก็บผลผลิตเครื่อง B → มีทั้งคู่; ฟักไข่สองเครื่องต่างใบ → น้องครบ; ป้อนน้องตัวเดียวกันสองเครื่อง; ลบของตกแต่งเครื่องหนึ่ง; เลเวลอัปสองฝั่ง; ขายซ้ำ → ไม่ติดลบ), base === local → ได้ remote เป๊ะ, idempotent (merge(b, x, x) = x), input ไม่ถูกแก้

## 2. ใช้การรวมในระบบเซฟ (B: js/storage.js)
- เก็บ **base** = สำเนาก้อนที่ขึ้น/ลงคลาวด์สำเร็จล่าสุด ใน localStorage `${key}_base` (ทุกครั้งที่ syncedStamp ถูกตั้งจาก cloud load/save) · guest ไม่มีคลาวด์ = ไม่ต้องมี
- ทุกจุดที่เดิม "เลือกก้อนใหม่กว่าแล้วทิ้งอีกก้อน" ระหว่างเครื่องนี้ที่มีของยังไม่ส่ง กับคลาวด์ที่ใหม่กว่า (`adoptCloud`, `handleRejectedWrite`, `reconcileAfterClaim` เมื่อ best = cloud แต่ memory/local มีของยังไม่ส่ง, `connectUser`): ถ้ามี base และ version เท่ากัน → `mergeSaves(base, local, cloud)` → ติดตั้งผลรวม + อัปโหลด (rev ต่อจากคลาวด์) + toast "🔄 รวมความคืบหน้าจาก 2 เครื่องแล้ว" · ไม่มี base / version ต่าง / merge throw → ทำแบบเดิม (ก้อนใหม่กว่าชนะ + backup)
- backup ยังทำเหมือนเดิมก่อนรวม (กันพลาด) · `MAX_BACKUPS` 3 → 6
- อัปโหลดเร็วขึ้นเมื่อมี action ของผู้เล่น: `CLOUD_INTERVAL_MS` 30 วิ → 10 วิ (tick-only drift คงเดิม 5 นาที) · `visibilitychange: hidden` / `pagehide` ส่งทันที (มีอยู่แล้ว — ตรวจว่าทำงานบน iOS: ใช้ `visibilitychange` เป็นหลัก)
- แท็บหลายแท็บเครื่องเดียว (BroadcastChannel single-writer) ใช้กลไกเดิม — ถ้าแท็บที่ yield มีของยังไม่ส่ง ให้รวมด้วยเช่นกัน
- tests (B: tests/v26b.test.js ใหม่) ด้วย fake cloud แบบใน tests/core.test.js (`setDbProvider`): สองเครื่อง (สองชุด storage state จำลอง) แต่ละเครื่องทำ action ต่างกันโดยไม่ sync → เครื่องหนึ่งขึ้นก่อน → อีกเครื่อง reconcile → ผลมีของทั้งสองฝั่ง, rev ถูก, ไม่มี loop เขียนวน · ไม่มี base → พฤติกรรมเดิม
