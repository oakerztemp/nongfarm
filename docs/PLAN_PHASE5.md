# PLAN PHASE 5 — ความสวยงามของภาพในเกม (เสนออนุมัติ)

> 2026-10-27 · หลัง deploy V19 · ผู้ใช้อยากให้เฟสต่อไปเน้นความสวยงามของภาพ

## สภาพตอนนี้ (สำรวจจากโค้ด)
- three.js r160: วัสดุ toon (`MeshToonMaterial` + gradient), แสง 2 ดวง (hemisphere + directional), เงาเป็นแผ่นกลมใต้ตัว (blob), ไม่มี tone mapping / post-processing
- ท้องฟ้า = gradient CSS หลัง canvas · "กลางคืน" = ตามธีมมืดของเครื่อง ไม่ใช่เวลาจริง
- หญ้า/ดอกไม้เป็นชิ้นนิ่ง ไม่ขยับ · น้ำในบ่อนิ่ง
- การ์ด/สมุด/รายการใช้อีโมจิของระบบ ซึ่งหน้าตาต่างกันระหว่าง iPhone / Android / Windows
- มีระบบระดับกราฟิก high / medium / low ลดระดับอัตโนมัติเมื่อเครื่องช้า: ใช้ต่อได้ เปิดของหนักเฉพาะ high

## เสนอ 3 รอบ (ทำทีละรอบ แต่ละรอบส่งภาพก่อน/หลังให้ดูก่อน deploy)

### V20 แสง สี และท้องฟ้า (ได้ผลมากที่สุดต่อแรงที่ใช้)
- ปรับโทนสีทั้งฉาก (tone mapping แบบ AgX/ACES + จัดพาเลตต์ใหม่) ให้สีนวลแบบเกมสไตล์ cozy ไม่จัดจ้าน
- **วงจรเวลาตามนาฬิกาจริง:** เช้า → กลางวัน → เย็นทองอร่าม (golden hour) → กลางคืน
  - กลางคืน: ดาว หิ่งห้อย และไฟโคมในลานที่เรืองแสง
  - ตัวเลือกในตั้งค่า: ใช้ตามธีมเครื่องแบบเดิม
- ท้องฟ้าแบบ 3D มีเมฆลอยช้าๆ และเงาเมฆพาดผ่านลาน
- **เงาจริงจากดวงอาทิตย์** (เฉพาะน้องและบ้าน, ระดับ high) · medium/low ใช้เงากลมเดิม

### V21 ตัวน้องสวยขึ้น
- **เส้นขอบตัวการ์ตูน (outline)** บางๆ สีเข้มกว่าขน · ไม่มีรอบดวงตา
- **แสงขอบตัว (rim light):** น้องดูเด่นจากพื้น
- ตาแวววาว (จุดไฮไลต์ขยับตามกล้อง) และแก้มชมพู
- **ระบบสีหน้า:** ปาก/คิ้วเปลี่ยนตามอารมณ์ ต่อยอดจากหน้าดีใจ/ร้องไห้ของ V19 ให้มีหลายแบบ: ง่วง หิว น้อยใจ ตื่นเต้น
- ท่าเล็กๆ ระหว่างยืนเฉยๆ: หายใจ กระดิกหู สะบัดหาง

### V22 ฉากมีชีวิต + ภาพในหน้า UI
- **ฉากมีชีวิต:**
  - หญ้าและดอกไม้ไหวตามลม (shader เบาๆ ปิดเองบนเครื่องช้า)
  - น้ำในบ่อเป็นประกาย มีระลอกรอบขอบ
  - ใบไม้และกลีบดอกปลิว
- **เอฟเฟกต์เรืองแสง (bloom) แบบเลือกเฉพาะจุด:** ออร่า Limited/ไชนี่ โคมลอยกระทง และไฟกลางคืนดูเรืองจริง (เฉพาะ high)
- **โหมดเล่นแบบซูม:** ฉากหลังเบลอนุ่ม (depth of field) ให้น้องเด่นเหมือนถ่ายรูป · โหมดถ่ายรูปได้ฟิลเตอร์และกรอบเพิ่ม
- **รูปน้องในหน้า UI เป็นรูปจากโมเดล 3D จริง:** ใช้ในการ์ด สมุดสัตว์ และรายการ แทนอีโมจิ ทุกเครื่องเห็นเหมือนกัน
  - วาดครั้งเดียวแล้วเก็บไว้ในเครื่อง ไม่หนักเครื่อง

## หลักที่ล็อกไว้ทุกรอบ
- ไม่แตะเศรษฐกิจ (econ sim ต้องผ่านเหมือนเดิม)
- **มือถือต้องลื่น:**
  - ของหนัก (เงาจริง, bloom, DOF, หญ้าไหว) เปิดเฉพาะระดับ high
  - ระบบลดระดับอัตโนมัติเดิมยังทำงาน
  - งบโมเดลเดิม (1,500/1,800 สามเหลี่ยม, ≤ 7 draw call ต่อตัว)
- ไม่เพิ่ม library ภายนอก: ใช้ addon ของ three.js r160 ที่ vendor มาเก็บในโปรเจกต์ (ไม่มี build step)
- ทุกรอบส่งภาพ render ก่อน/หลัง (โฟลเดอร์ docs/design) ให้อนุมัติก่อนลงมือจริง และถามก่อน deploy (หรือตามที่สั่ง)
